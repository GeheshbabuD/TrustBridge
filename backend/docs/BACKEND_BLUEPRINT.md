## Target architecture
Client → Express /api/v1 → security/auth/role/validation middleware → routes/controllers → domain services/state machine → models/Prisma → PostgreSQL. Provider adapters for payment, notifications, AI and blockchain. Use outbox/retries, idempotency and reconciliation. Money uses integer minor units and currency. AI advisory only; personal/confidential data off-chain.

## Financial and state invariants
Every payment attempt, provider event, escrow authorization, payout/refund, and ledger journal has its own state and unique idempotency key. Provider capture/refund/payout outcomes are verified independently from client claims. Authorization, provider execution, ledger posting and final transaction-state transition are distinct steps with durable history. Use optimistic version checks or row-level locking for transaction/escrow state; retry serialization conflicts only with bounded policy. A balanced append-only double-entry journal is committed atomically with the corresponding internal state/history/outbox. Provider reconciliation detects external/internal mismatch; no silent ledger edits.
