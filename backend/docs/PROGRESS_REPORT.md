## TB-BE-034E update — 2026-11-03

Purpose-bound step-up is implemented at `POST /api/v1/auth/mfa/step-up/challenge` and `/verify`. The default challenge lifetime is five minutes (validated range 60–600 seconds); durable attempts cap at five, with separate process-local IP limits defaulting to five per ten minutes. Challenge hashes are bound to user, refresh session, authVersion, registered operation purpose/resource, and exact MFA activation timestamp. Verification atomically claims the TOTP replay step and consumes the challenge, recording server `verifiedAt`. It creates no token or session. `createStepUpAuthorizationMiddleware` requires a consumed, recent grant for the exact account/session/operation/resource and current enrollment; existing role/ownership checks remain mandatory.

The only registered purpose is `MFA_RECOVERY_CODES_REGENERATE` on the authenticated user's own User record; no recovery-code regeneration endpoint or other business operation was added.
